## 5. Backend blockers found (documented only, not fixed)

1. **AI report generation is broken in the original backend.**
   - Endpoint: `POST /api/reports` (`backend/src/routes/reports.routes.js:21`).
   - `backend/src/services/reports.service.js:7-9` destructures `generate` from `backend/src/integrations/ai-service/reports.js`.
   - `backend/src/integrations/ai-service/reports.js:24` exports only `{ callService }`.
   - Result: `TypeError: generateAIReport is not a function` at `backend/src/services/reports.service.js:178`; HTTP `500` with generic message.
   - Why frontend-only changes cannot resolve it: the missing export and call site are backend implementation defects. The frontend can only send the request and surface the real failure; it cannot make the backend function exist without changing backend source.

2. **No live canonical survey share-link or QR endpoint.**
   - Missing endpoints: `GET /api/surveys/:id/share`, `GET /api/surveys/:id/qr`.
   - They are commented out at `backend/src/routes/survey.routes.js:9` and `backend/src/routes/survey.routes.js:69-71`; `backend/src/services/share.service.js` is entirely commented out.
   - Why frontend-only changes cannot resolve it: no API response supplies a canonical short URL or QR payload. The frontend now derives an honest same-origin hash link from the real `shortCode` in `GET /api/surveys`; inventing a share endpoint would violate the no-invention rule.

3. **Backend survey-link fallback uses a different origin and unserved path.**
   - `backend/src/utils/surveyLinks.js:11` falls back to `http://localhost:5173` via `FRONTEND_URL`.
   - `backend/src/utils/surveyLinks.js:12,15,17` builds `/s/<code>` paths.
   - Configured origin is `APP_ORIGIN=http://127.0.0.1:5173`; the client is hash-routed and has no `/s` route.
   - Why frontend-only changes cannot resolve it: the builder is backend code and its consumers are currently commented out. The frontend avoids the mismatch by building links from `window.location.origin`, but cannot change the backend fallback or make backend-generated `/s` links canonical.

4. **Public survey submission is gated by exact browser Origin/CSRF.**
   - Endpoint: `POST /api/public/surveys/:shortCode/responses`.
   - Global middleware: `backend/app.js:37`.
   - Exact check: `backend/src/utils/browserSession.js:31-55`, with comparison at line 41 and `403 CSRF_REJECTED` at lines 48-52.
   - Why frontend-only changes cannot resolve it: allowing a second origin would require a backend origin-policy change and would weaken CSRF. The frontend keeps links same-origin and does not bypass the check.

5. **Email verification/resend endpoint is absent.**
   - Missing endpoint: `POST /api/auth/resend-verification`.
   - `apps/web/src/features/auth/api.js:21-22` still defines the adapter, but connected verification routes are guarded as under development in `AppRouter.jsx:503-517`, so no user-reachable production button calls it; preview resend stays local.
   - Why frontend-only changes cannot resolve it: there is no controller/route to call; registration signs in directly.

6. **No production Evidence contract.**
   - Missing endpoint: no `/api/.../evidence` or per-action evidence lookup exists.
   - Why frontend-only changes cannot resolve it: preview IDs such as `1248` are not owned response IDs. Mapping them to production data would invent a contract or expose unrelated data.

7. **Root lint/format checks are blocked by unchanged backend files.**
   - `backend/src/controllers/overviewAnalytics.controller.js:33:31` — `no-irregular-whitespace`.
   - `backend/src/controllers/overviewTrends.controller.js:85:37` — `no-irregular-whitespace`.
   - `pnpm format:check` also reports style issues in unchanged backend and pre-existing files. Frontend-only lint and Prettier checks pass.

8. **Other weak points observed but not changed.**
   - `backend/src/routes/overview.routes.js:20` has a weaker auth posture on `/api/trends`.
   - Some overview controllers return raw error/status payloads rather than the shared error envelope.
   - Read-only backend serial tests: `54` tests, `52` pass, `2` fail; both failures are the report-generation mismatch above.

9. **No backend contracts for several planned surfaces.**
   - No notification inbox feed, generic file upload, multi-business creation, subscription/billing, or help/content API is registered in `backend/src/routes`.
   - Why frontend-only changes cannot resolve them: each would need new backend routes, validation, ownership rules and persistence. The frontend keeps these surfaces honest and unavailable instead of inventing responses.

10. **Read-only UI audit observations (not user-reachable regressions).**
    - `upload-file` is dispatched only from the preview dashboard design; production dashboard renders `ConnectedFeaturePage`, and the action falls through to the honest unavailable notice.
    - `#/survey-create` is a registered design variant. In connected production it intentionally collapses to the connected survey list; the real create action uses `#/surveys?create=1`, which opens the real create editor and was browser-tested.
    - `MotionPreviewBar` links to three HTML files that do not exist in this repository, but the component is not rendered anywhere in the current app.
